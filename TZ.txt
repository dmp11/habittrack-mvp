Техническое задание: трекер привычек со статистикой (MVP)
1. Общие сведения
Наименование: HabitTrack MVP.
Тип: веб‑приложение (SPA) + REST API.
Целевая аудитория: 18–45 лет, пользователи без технических навыков.
Цель: фиксация ежедневных привычек, визуализация прогресса, простая статистика.
2. Функциональные требования
Регистрация и авторизация
Форма регистрации: email, пароль, имя (опционально).
Авторизация по email/паролю.
Восстановление пароля через email.
Хранение сессии: JWT (access + refresh).
Управление привычками
Создание привычки: название, тип (бинарная/счётчик), частота (ежедневно/по дням недели), целевое значение (для счётчика), описание (опционально).
Редактирование/удаление привычки.
Статус привычки: активна/архив.
Отметки о выполнении
Для бинарной привычки: кнопка «Сделано»/«Пропущено» на текущую дату.
Для счётчика: ввод значения за день (валидация: ≥0, ≤9999).
Возможность редактирования отметки за прошедшие дни (в пределах 30 дней).
Статистика и визуализация
Календарь активности (тепловая карта) за 30 дней: зелёный — выполнено, красный — пропущено, серый — не отмечено.
График динамики (линейный) для счётчиков: среднее значение за неделю/месяц.
Метрики: общее количество выполненных дней, текущая серия (streak), процент выполнения за 7/30 дней.
Экспорт статистики: CSV (дата, привычка, тип, значение).
Уведомления
Напоминание в 18:00 (по часовому поясу пользователя): «Не забудьте отметить привычки!».
Формат: email + push (опционально, если есть PWA).
3. Нефункциональные требования
Производительность: загрузка страницы ≤2 сек (3G), API latency ≤300 мс.
Безопасность: HTTPS, хеширование паролей (bcrypt), защита от CSRF/XSS, rate limiting на регистрацию/авторизацию.
Доступность: поддержка мобильных устройств (Mobile‑first), контрастность ≥4.5:1.
Локализация: интерфейс на русском, даты/время — по часовому поясу пользователя.
4. Форматы данных
API (REST)
POST /auth/register — регистрация.
POST /auth/login — авторизация.
GET /habits — список привычек.
POST /habits — создание привычки.
PATCH /habits/{id} — редактирование.
POST /records — отметка о выполнении.
GET /stats — статистика (агрегаты + графики).
GET /stats/export — экспорт CSV.
Пример JSON (создание привычки)
json
{
  "name": "Пить воду",
  "type": "counter",
  "frequency": ["mon","tue","wed","thu","fri","sat","sun"],
  "target": 2000,
  "unit": "мл"
}
Пример CSV (экспорт)
csv
date,habit_name,type,value
2024-06-01,Пить воду,counter,2100
2024-06-01,Читать 20 мин,binary,1
5. Этапы разработки
Этап	Задачи	Формат результата	Срок
1. Прототип UI	Wireframes (регистрация, список привычек, календарь, статистика)	Figma (3–5 экранов)	2 дня
2. Backend MVP	Авторизация, CRUD привычек, хранение отметок, базовая статистика	REST API + БД (PostgreSQL)	5 дней
3. Frontend MVP	SPA (React/Vue), формы, календарь, графики (Chart.js)	Сборка (Webpack/Vite)	5 дней
4. Интеграции	Email‑уведомления, экспорт CSV, валидация данных	Настроенные сервисы	2 дня
5. Тестирование	Unit/интеграционные тесты, проверка на мобильных	Отчёт, баг‑репорты	3 дня
6. Деплой	Docker‑контейнеры, CI/CD (GitHub Actions), хостинг (Render/Railway)	Рабочий URL, документация API	2 дня
6. Стек технологий (рекомендуемый)
Frontend: React + TypeScript, Tailwind CSS, Chart.js.
Backend: Node.js (Express) или Python (FastAPI), PostgreSQL, Redis (кэш).
Инфраструктура: Docker, GitHub Actions, Render/Railway.
7. Критерии приёмки
Все API‑эндпоинты возвращают корректные статусы (2xx/4xx/5xx).
Статистика пересчитывается в реальном времени после отметки.
Экспорт CSV содержит данные за последние 30 дней.
Интерфейс корректно отображается на iPhone SE и Samsung Galaxy S20.
Пароли не хранятся в открытом виде.
8. Приоритеты (MoSCoW)
Must: регистрация/авторизация, создание привычек, отметки, календарь, базовая статистика.
Should: экспорт CSV, уведомления, редактирование прошлых дней.
Could: тёмная тема, цели на месяц, импорт из CSV.
Won’t: геймификация, соцсети, офлайн‑режим.
